## 项目概述

MaiBot 是一个基于大语言模型(LLM)的拟人化QQ群聊AI机器人。她不仅仅是一个机器人，而是致力于成为一个活跃在 QQ 群聊中的"生命体"。她不追求完美，但追求真实。

### 核心特性

- **💭 拟人化交互**: 使用自然语言风格构建 Prompt，回复贴近人类习惯
- **🎭 行为规划**: 懂得在合适的时间说话，使用合适的动作
- **🧠 表达学习**: 模仿群友的说话风格，学习黑话，不断进化
- **🔌 插件系统**: 提供强大的 API 和事件系统，无限扩展可能
- **💝 情感表达**: 拥有独立的情绪系统和表情包互动能力
- **📚 记忆系统**: 长期记忆和短期记忆管理，全局记忆支持
- **🔍 知识库**: LPMM(Large Personal Memory Model)知识库支持，可视化知识图谱
- **💫 心流系统**: 智能的对话节奏控制，动态思考力度机制
- **🌙 梦境系统**: 麦麦做梦功能，让AI更有生命感
- **🌐 WebUI**: 提供强大的Web管理界面进行配置和监控
- **💬 本地聊天室**: 直接在 WebUI 与麦麦聊天，支持用户和平台模拟

### 设计理念

> **"最像而不是好"** - 千石可乐

MaiBot 的核心设计理念是创造一个尽可能让人感知到真实的类人存在，而不是一个功能齐全的"helpful assistant"。她会犯错，拥有自己的感知和想法，是一个你无法完全掌控的个体。

## 核心模块详解

### 1. 入口程序 (bot.py)

**架构**: 双进程架构

- **Runner进程**: 守护进程，负责启动和监控Worker进程
- **Worker进程**: 实际运行MaiCore的进程

**重启机制**:
- 退出码 `42` 表示重启请求
- 支持 `Ctrl+C` 信号优雅关闭
- 自动重启失败的Worker进程

**启动命令**:
```bash
# 正常启动
python bot.py

# 测试模式(不连接QQ)
python bot.py --test

# 带UI测试模式
python bot.py --test-with-ui
```

### 4. 聊天系统 (src/chat/)

**消息处理流程**:

```
消息接收 -> 消息预处理 -> 事件处理(ON_MESSAGE)
  -> 心流判断 -> Planner规划Action -> 事件处理(ON_PLAN)
  -> Action执行 -> 回复生成 -> 事件处理(POST_LLM)
  -> 后处理(表情、表达) -> 事件处理(POST_SEND)
  -> 消息发送 -> 事件处理(AFTER_SEND)
```

```python
from typing import List, Tuple, Type, Dict, Any, Union
from src.plugin_system import (
    PluginBase,
    register_plugin,
    BaseAction,
    BaseCommand,
    BaseEventHandler,
    ComponentInfo,
    ConfigField,
)

@register_plugin
class MyPlugin(PluginBase):
    """我的插件"""
    
    @property
    def plugin_name(self) -> str:
        return "my_plugin"
    
    @property
    def enable_plugin(self) -> bool:
        return True
    
    @property
    def dependencies(self) -> List[str]:
        return []  # 依赖的其他插件
    
    @property
    def python_dependencies(self) -> List:
        return []  # Python包依赖
    
    @property
    def config_file_name(self) -> str:
        return "config.toml"
    
    @property
    def config_schema(self) -> Dict[str, Union[Dict[str, ConfigField], str]]:
        """配置Schema定义"""
        return {
            "basic": {
                "enabled": ConfigField(
                    type="boolean",
                    default=True,
                    description="是否启用插件",
                    required=True
                ),
                "api_key": ConfigField(
                    type="string",
                    default="",
                    description="API密钥",
                    required=False
                )
            }
        }
    
    def get_plugin_components(self) -> List[Tuple[ComponentInfo, Type]]:
        """返回插件包含的组件"""
        return [
            (MyAction.get_action_info(), MyAction),
            (MyCommand.get_command_info(), MyCommand),
        ]
```

        if not enabled:

        await self.send_text("这是一个示例动作!")
        
        # 记录日志

        return True, "动作执行成功"

## 常见问题

### Q1: 配置文件不生效

**症状**: 修改配置后没有变化

**解决方案**:
1. 确保配置文件在 `config/bot_config.toml`
2. 检查 TOML 格式是否正确
3. 重启机器人使配置生效
4. 查看日志中的配置加载信息

```bash
# 验证 TOML 格式
python -c "import toml; print(toml.load('config/bot_config.toml'))"
```

### Q2: 插件无法加载

**症状**: 插件不工作或启动时报错

**解决方案**:
1. 检查 `_manifest.json` 格式是否正确
2. 确认插件类继承自 `PluginBase`
3. 检查插件依赖是否已安装
4. 查看日志中的插件加载错误信息

```bash
# 安装插件依赖
uv pip install -r plugins/your_plugin/requirements.txt
```

### Q3: LLM调用失败

**症状**: 机器人不回复或回复错误

**解决方案**:
1. 检查 `model_config.toml` 中的API密钥配置
2. 确保网络连接正常
3. 检查API余额是否充足
4. 查看日志中的LLM调用错误
5. 尝试切换到其他模型

### Q4: 消息发送失败

**症状**: 消息无法发送到QQ

**解决方案**:
1. 检查消息长度是否超过限制
2. 检查消息格式是否正确
3. 确认QQ协议端连接正常
4. 检查是否被风控
5. 查看协议端日志

### Q5: WebUI 无法访问

**症状**: 无法打开 WebUI 页面

**解决方案**:
1. 检查 WebUI 是否已启用 (`webui.enabled = true`)
2. 确认端口未被占用
3. 检查防火墙设置
4. 尝试使用 `127.0.0.1` 而不是 `localhost`
5. 查看 WebUI 启动日志

### Q6: 内存占用过高

**症状**: 机器人运行一段时间后内存占用很高

**解决方案**:
1. 调整记忆保留天数 (`memory.memory_retention_days`)
2. 清理旧的日志文件
3. 定期重启机器人
4. 优化插件代码，避免内存泄漏
5. 使用数据库清理脚本

### Q7: 表达学习效果不好

**症状**: 学习的表达不自然或不准确

**解决方案**:
1. 启用表达自动评估 (`expression.enable_auto_evaluation`)
2. 手动评估和筛选表达
3. 调整表达学习阈值
4. 使用 WebUI 黑话管理功能
5. 查看表达评估日志

### Q8: Docker 部署问题

**症状**: Docker 容器无法启动或运行异常

**解决方案**:
1. 检查 `docker-compose.yml` 配置
2. 确保配置文件已正确挂载
3. 检查容器日志: `docker-compose logs -f`
4. 确认端口映射正确
5. 重新构建镜像: `docker-compose build --no-cache`

### Q9: 知识库检索不准确

**症状**: LPMM 检索结果不相关

**解决方案**:
1. 调整检索相似度阈值
2. 优化知识条目质量
3. 使用知识图谱可视化检查知识结构
4. 定期刷新知识库索引
5. 使用测试脚本验证检索效果

```bash
python scripts/test_lpmm_retrieval.py
```

### Q10: 梦境系统不工作

**症状**: 麦麦不做梦或梦境内容异常

**解决方案**:
1. 确认梦境系统已启用 (`dream.enabled = true`)
2. 检查梦境间隔设置
3. 确保有足够的记忆和知识作为梦境素材
4. 查看梦境生成日志
5. 调整梦境生成参数
