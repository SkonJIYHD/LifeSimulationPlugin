# 事件及人体模拟插件设计文档（AI驱动版本 v1.1.0）

> 生成日期: 2026-01-13
> 插件名称: LifeSimulationPlugin
> 插件版本: 1.1.0
> 架构类型: AI驱动

---

## 一、插件概述

### 1.1 插件目标
创建一个AI驱动的事件及人体模拟插件，让机器人具有真实人类的生理状态、日常活动、社交行为和环境感知能力，使机器人更加拟人化和生动。

### 1.2 核心特性（AI驱动版本 v1.1.0）
- **AI驱动的日程生成**: AI根据人格、习惯和当前状态生成日程
- **AI驱动的随机事件生成**: AI根据当前情境生成随机事件
- **生病系统**: AI多维度判断是否生病，生病后自动调整日程
- **健康状态由事件决定**: 健康状态由随机事件和日程决定
- **习惯系统**: 习惯可以配置或由AI根据人格生成
- **节日API集成**: 通过API动态获取节假日信息
- **AI驱动的情绪判断**: AI根据多方面因素判断情绪
- **可编辑的AI提示词**: 提示词在配置文件中，可自定义
- **AI生成话语**: 所有对话由AI生成，不固定
- **只读生理状态**: 生理状态数据不能通过命令修改
- **自定义时间/日期API**: 支持用户自定义时间日期获取方式
- **可配置AI模型**: 支持9种模型配置类型
- **习惯工具**: LLM可调用工具获取习惯信息

### 1.3 设计原则
1. **AI优先**: 尽可能让AI做决策，减少硬编码逻辑
2. **动态生成**: 日程、事件、情绪等都由AI动态生成
3. **拟人化**: 模拟真实人类的行为和决策过程
4. **可配置**: 提供灵活的配置选项，包括AI提示词
5. **状态保护**: 生理状态数据不可随意修改

## 二、功能模块设计

### 2.1 生理状态模拟模块

#### 2.1.1 睡眠/清醒状态
**功能描述**: 模拟人类的睡眠周期，包括入睡、深睡、浅睡、醒来等状态。

**状态定义**:
- `AWAKE`: 清醒状态
- `SLEEPY`: 困倦状态
- `FALLING_ASLEEP`: 入睡中
- `LIGHT_SLEEP`: 浅睡状态
- `DEEP_SLEEP`: 深睡状态
- `WAKING_UP`: 醒来中

#### 2.1.2 疲劳度
**疲劳度范围**: 0-100
- 0-20: 精力充沛
- 21-40: 精力良好
- 41-60: 轻微疲劳
- 61-80: 明显疲劳
- 81-100: 严重疲劳

**变化规则**:
- 消息时略微增加
- 由随机事件影响

#### 2.1.3 饥饿度
**饥饿度范围**: 0-100
- 0-20: 不饿
- 21-40: 轻微饥饿
- 41-60: 饥饿
- 61-80: 很饿
- 81-100: 非常饿

**变化规则**:
- 消息时略微增加
- 由随机事件影响

#### 2.1.4 健康状态（生病系统）
**功能描述**: 模拟人类的健康状态，影响行为和状态。

**健康状态类型**:
- `HEALTHY`: 健康
- `RECOVERING`: 康复中
- `SLIGHTLY_ILL`: 轻微不适
- `ILL`: 生病
- `SERIOUSLY_ILL`: 严重生病

**健康度范围**: 0-100（越高越健康）
- 80-100: 健康
- 60-79: 康复中
- 40-59: 轻微不适
- 20-39: 生病
- 0-19: 严重生病

**生病系统特点**:
- AI多维度判断是否生病（疲劳度、饥饿度、情绪、当前活动、人格特点）
- 生病后自动重新生成符合病情的日程
- 康复后自动重新生成正常日程
- 健康度越高越健康

**配置项**:
```toml
[schedule]
illness_system_enabled = true
illness_probability_multiplier = 1.0
auto_regenerate_on_illness = true
```

#### 2.1.5 情绪状态
**功能描述**: 模拟人类的情绪状态，影响行为和回复。

**情绪类型**:
- `HAPPY`: 开心
- `SAD`: 伤心
- `ANGRY`: 生气
- `ANXIOUS`: 焦虑
- `EXCITED`: 兴奋
- `CALM`: 平静
- `TIRED`: 疲惫
- `BORED`: 无聊

**情绪强度**: 0-100
- 0-20: 轻微
- 21-40: 一般
- 41-60: 明显
- 61-80: 强烈
- 81-100: 非常强烈

### 2.2 日常活动模拟模块

#### 2.2.1 日程生成
**功能描述**: AI根据当前情况生成日程安排。

**日程特点**:
- 根据健康状态自动调整
- 考虑疲劳度、饥饿度
- 考虑时间、星期、周末、节假日
- 考虑人格特点和个人习惯

**活动类型**:
- work: 工作
- leisure: 休闲
- meal: 用餐
- sleep: 睡眠
- exercise: 运动
- study: 学习
- other: 其他
- rest: 休息
- medical: 医疗

### 2.3 事件触发系统

#### 2.3.1 随机事件生成
**功能描述**: AI根据当前情境生成随机事件。

**事件类型**:
- health: 健康事件（生病、康复）
- social: 社交事件
- work: 工作事件
- leisure: 休闲事件
- emotion: 情绪事件
- other: 其他事件

**事件影响**:
- health_impact: 对健康的影响（-10到10）
- fatigue_impact: 对疲劳的影响（-10到10）
- hunger_impact: 对饥饿的影响（-10到10）
- emotion_impact: 对情绪的影响（-10到10）
- probability: 发生概率（0.0-1.0）

**生病事件类型**:
- 轻微不适: -5到-10
- 生病: -10到-20
- 严重生病: -20到-30
- 康复事件: +5到+15

### 2.4 习惯系统

#### 2.4.1 个人习惯
**功能描述**: 定义个人习惯和偏好。

**习惯类型**:
- 说话习惯
- 行为习惯
- 兴趣爱好
- 偏好设置

**配置方式**:
- 手动配置
- AI根据人格特点自动生成

**访问方式**:
- 插件内部状态
- LLM通过工具调用访问

### 2.5 环境感知模块

#### 2.5.1 时间感知
**功能描述**: 感知当前时间，调整行为。

**时间/日期获取方式**:
-_builtin_: 使用内置datetime
- _custom_: 使用自定义API

**配置项**:
```toml
[time_api]
method = "builtin"
url = ""
timeout = 5
```

#### 2.5.2 节日感知
**功能描述**: 感知节日，调整行为。

**节日API**:
- 使用免费中国节日API (timor.tech)
- 手动检查常见节日
- 节日信息缓存（24小时）

### 2.6 AI模型配置

#### 2.6.1 可用模型配置
- **utils**: 工具模型（表情包、取名、关系、情绪等）
- **tool_use**: 工具调用模型
- **replyer**: 回复生成模型
- **planner**: 决策模型
- **vlm**: 图像识别模型
- **voice**: 语音识别模型
- **embedding**: 嵌入模型
- **lpmm_entity_extract**: 实体提取模型
- **lpmm_rdf_build**: RDF构建模型

**配置项**:
```toml
[ai]
schedule_model = "replyer"
event_model = "tool_use"
emotion_model = "planner"
habit_model = "replyer"
temperature = 0.7
max_tokens = 1000
```

## 三、插件组件设计

### 3.1 Action 组件

#### 3.1.1 PerformActivityAction
**功能**: 执行日程中的活动

**激活类型**: ALWAYS

**特点**:
- 执行日程中的活动
- 更新当前活动状态
- 发送AI生成的响应

#### 3.1.2 HandleEventAction
**功能**: 处理随机事件

**激活类型**: ALWAYS

**特点**:
- 处理随机事件
- 应用事件影响
- 发送AI生成的响应
- 健康状态变化时自动重新生成日程

### 3.2 Command 组件

#### 3.2.1 StatusCommand
**功能**: 查询当前状态

**命令**: `/life_status`

**显示内容**:
- 睡眠状态
- 疲劳度
- 饥饿度
- 健康度
- 情绪
- 当前活动
- 节日信息

#### 3.2.2 ScheduleCommand
**功能**: 查询日程安排

**命令**: `/life_schedule`

**显示内容**:
- AI生成的日程
- 日程生成日期
- 活动详情和优先级

### 3.3 EventHandler 组件

#### 3.3.1 StartupHandler
**功能**: 启动事件处理器

**事件类型**: ON_START

**功能**:
- 启动调度器
- 加载保存的状态
- 确保习惯已设置
- 检查配置文件提示词

#### 3.3.2 StopHandler
**功能**: 停止事件处理器

**事件类型**: ON_STOP

**功能**:
- 停止调度器
- 保存状态
- 清理后台任务

#### 3.3.3 StateUpdateHandler
**功能**: 状态更新处理器

**事件类型**: ON_START

**功能**:
- 状态更新由调度器循环处理

#### 3.3.4 MessageEventHandler
**功能**: 消息事件处理器

**事件类型**: ON_MESSAGE

**功能**:
- 消息时略微增加疲劳度
- 消息时略微增加饥饿度

### 3.4 Tool 组件

#### 3.4.1 GetHabitsTool
**功能**: 获取个人习惯信息

**名称**: `get_life_simulation_habits`

**描述**: 获取生活模拟插件中的个人习惯信息，包括说话习惯、行为习惯、兴趣爱好和偏好设置

**参数**: 无

**可用性**: 可供LLM调用

**返回内容**:
```json
{
  "name": "get_life_simulation_habits",
  "content": "说话习惯: 喜欢用表情, 喜欢用语气词\n行为习惯: 早起, 爱运动\n兴趣爱好: 音乐, 电影, 游戏\n偏好设置: food_preference: 甜食, music_preference: 流行音乐",
  "habits": {
    "speaking_habits": ["喜欢用表情", "喜欢用语气词"],
    "behavior_habits": ["早起", "爱运动"],
    "interests": ["音乐", "电影", "游戏"],
    "preferences": {"food_preference": "甜食", "music_preference": "流行音乐"}
  }
}
```

## 四、配置文件设计

### 4.1 插件配置文件

**文件名**: `config.toml`

**主要配置节**:

```toml
[plugin]
enabled = true
update_interval = 60
data_dir = "data"

[ai]
schedule_model = "replyer"
event_model = "tool_use"
emotion_model = "planner"
habit_model = "replyer"
temperature = 0.7
max_tokens = 1000

[prompts]
schedule_generation = "..."
random_event_generation = "..."
emotion_judgment = "..."
habit_generation = "..."

[habits]
use_ai_generation = true
speaking_habits = []
behavior_habits = []
interests = []

[schedule]
regenerate_daily = true
random_event_probability = 0.1
illness_system_enabled = true
illness_probability_multiplier = 1.0
auto_regenerate_on_illness = true

[time_api]
method = "builtin"
url = ""
timeout = 5

[holiday_api]
enabled = true
url = "https://timor.tech/api/holiday/info/{date}"
cache_duration = 86400
timeout = 5

[commands]
enabled = true

[state]
filename = "state.json"
auto_save_interval = 300

[logging]
level = "INFO"
verbose = false
```

**提示词配置**:
- 所有提示词都在配置文件中
- 支持变量替换
- 留空使用默认提示词

### 6.2 关键设计决策（v1.1.0）

#### 6.2.1 提示词在配置文件中
**决策**: 所有提示词都在配置文件中，不再硬编码。

**实现方式**:
- 提示词存储在 `config.toml` 的 `[prompts]` 部分
- 首次运行时自动生成包含提示词的配置文件
- 支持用户自定义
- 留空使用默认提示词

#### 6.2.2 移除 i18n 系统
**决策**: 移除国际化系统，简化代码结构。

**原因**: 用户反馈 i18n 没什么用。

#### 6.2.3 自定义时间/日期API
**决策**: 支持用户自定义时间日期获取方式。

**实现方式**:
- builtin: 使用内置datetime
- custom: 使用自定义API
- 配置URL和超时

#### 6.2.4 生病系统
**决策**: AI多维度判断是否生病，生病后自动调整日程。

**实现方式**:
- AI根据疲劳度、饥饿度、情绪、当前活动、人格特点判断
- 健康度越高越健康
- 生病后自动重新生成符合病情的日程
- 康复后自动重新生成正常日程

#### 6.2.5 习惯工具
**决策**: 提供工具让LLM访问习惯信息。

**实现方式**:
- `GetHabitsTool` 工具组件
- 可供LLM调用
- 返回格式化的习惯信息

## 八、总结

本插件设计并实现了一个完整的事件及人体模拟系统，包含以下核心功能：

1. **生理状态模拟**: 睡眠、疲劳、饥饿、健康（生病系统）、情绪等状态
2. **日常活动模拟**: AI驱动的日程生成
3. **事件触发系统**: AI驱动的随机事件生成
4. **习惯系统**: 配置+AI生成，LLM可访问
5. **环境感知**: 时间（可自定义）、节日
6. **状态管理**: 持久化、查询
7. **AI模型配置**: 支持9种模型配置类型
8. **提示词系统**: 提示词在配置文件中

插件提供了 2 个 Action 组件、2 个 Command 组件、4 个 EventHandler 组件和 1 个 Tool 组件，全面覆盖了事件及人体模拟的各个方面。

通过这个插件，机器人将具有更真实的拟人化行为，能够模拟人类的日常活动、生理状态、生病过程和社交行为，使与机器人的交互更加自然和有趣。
