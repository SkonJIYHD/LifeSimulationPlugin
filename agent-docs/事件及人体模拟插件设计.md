## 一、插件概述

### 1.1 插件目标
创建一个AI驱动的事件及人体模拟插件，让机器人具有真实人类的生理状态、日常活动、社交行为和环境感知能力，使机器人更加拟人化和生动。

### 1.2 核心特性（AI驱动版本 v1.7.0）
- **AI驱动的日程生成**: AI根据人格、习惯和当前状态生成日程
- **AI驱动的随机事件生成**: AI根据当前情境生成随机事件
- **生病系统**: AI多维度判断是否生病，生病后自动调整日程
- **健康状态由事件决定**: 健康状态由随机事件和日程决定
- **习惯系统**: 习惯可以配置或由AI根据人格生成
- **节日API集成**: 通过API动态获取节假日信息
- **AI驱动的情绪判断**: AI根据多方面因素判断情绪
- **可编辑的AI提示词**: 提示词在配置文件中，可自定义
- **AI生成话语**: 所有对话由AI生成，不固定
- **只读生理状态**: 生理状态数据不能通过命令修改
- **自定义时间/日期API**: 支持用户自定义时间日期获取方式
- **可配置AI模型**: 支持9种模型配置类型
- **习惯工具**: LLM可调用工具获取习惯信息
- **社交网络系统**: 记录用户关系，实现个性化社交行为
- **亲密度系统**: 通过互动积累和衰减机制管理亲密度
- **关系管理**: 支持9种关系类型（陌生人、熟人、朋友、好友、挚友、家人、伴侣、敌人、拉黑）
- **关系设置工具**: LLM可调用工具设置用户关系类型（v1.6.0）
- **工具参数格式修复**: 修复工具参数格式，符合BaseTool要求（v1.6.0）

- **社交网络查询命令**: 支持手动查询社交网络信息（v1.6.0）
- **完整组件注册**: 16个组件全部正确注册（6个EventHandler、2个Action、5个Tool、3个Command）（v1.6.0）
- **状态查询工具**: LLM可调用工具获取当前状态信息（v1.6.0）

## 二、功能模块设计

### 2.1 生理状态模拟模块

#### 2.1.1 睡眠/清醒状态（v1.6.0 增强）
**功能描述**: 模拟人类的睡眠周期，包括入睡、深睡、浅睡、醒来等状态。睡眠期间机器人不会回复消息，实现真实的睡眠行为。睡眠系统与日程系统联动，支持AI决定自动回复，并可被消息打扰唤醒。

**状态定义**:
- `AWAKE`: 清醒状态 - 正常活动，可以回复消息
- `SLEEPY`: 困倦状态 - 疲劳度较高，准备入睡，可以回复消息但可能反应较慢
- `FALLING_ASLEEP`: 入睡中 - 正在入睡，不回复消息
- `LIGHT_SLEEP`: 浅睡状态 - 轻度睡眠，不回复消息，可能被吵醒
- `DEEP_SLEEP`: 深睡状态 - 深度睡眠，不回复消息，疲劳度快速恢复，难以被吵醒
- `WAKING_UP`: 醒来中 - 正在醒来，不回复消息

**睡眠状态转换逻辑**:

1. **入睡过程**:
   ```
   AWAKE -> SLEEPY -> FALLING_ASLEEP -> LIGHT_SLEEP -> DEEP_SLEEP
   ```
   - `AWAKE -> SLEEPY`: 
     - 当前日程为睡眠活动（优先）
     - 或疲劳度 > 70 或时间接近睡觉时间
   - `SLEEPY -> FALLING_ASLEEP`: 
     - 当前日程为睡眠活动（优先）
     - 或疲劳度 > 80 或到达睡觉时间
   - `FALLING_ASLEEP -> LIGHT_SLEEP`: 5-10分钟后
   - `LIGHT_SLEEP -> DEEP_SLEEP`: 20-30分钟后

2. **醒来过程**:
   ```
   DEEP_SLEEP -> LIGHT_SLEEP -> WAKING_UP -> AWAKE
   ```
   - `DEEP_SLEEP -> LIGHT_SLEEP`: 
     - 当前日程为起床活动（优先）
     - 或睡眠时长达到最小睡眠时间
     - 或被消息打扰唤醒（概率较低）
   - `LIGHT_SLEEP -> WAKING_UP`: 
     - 当前日程为起床活动（优先）
     - 或被消息打扰唤醒（概率中等）
   - `WAKING_UP -> AWAKE`: 5-10分钟后

**日程联动机制**:
- **自动入睡**: 当当前日程活动类型为 `sleep` 时，自动进入睡眠状态
- **自动醒来**: 当当前日程活动类型从 `sleep` 变为其他活动时，自动醒来
- **日程优先**: 日程活动优先于疲劳度和时间判断
- **智能检测**: 每分钟检查当前日程活动，自动切换睡眠状态

```python
def check_schedule_based_sleep(self, current_time: datetime):
    """基于日程检查睡眠状态"""
    current_activity = self._get_current_activity(current_time)
    
    if current_activity and current_activity.get('activity') == 'sleep':
        # 当前日程为睡眠，应该入睡
        if self.sleep_state == SleepState.AWAKE:
            self._start_sleeping(current_time)
    else:
        # 当前日程不是睡眠，应该醒来
        if self.sleep_state in [SleepState.LIGHT_SLEEP, SleepState.DEEP_SLEEP]:
            self._start_waking_up(current_time)
```

**睡眠触发条件**（优先级从高到低）:
1. **日程联动**: 当前日程活动为 `sleep` 类型（最高优先级）
2. **疲劳度触发**: 疲劳度 > 80（自动触发）
3. **时间触发**: 时间接近睡觉时间
4. **手动触发**: 通过命令手动触发（可选）

**醒来触发条件**（优先级从高到低）:
1. **日程联动**: 当前日程活动从 `sleep` 变为其他活动（最高优先级）
2. **消息打扰**: 浅睡时被大量消息吵醒（可配置）
3. **时长限制**: 睡眠时长达到最大睡眠时间
4. **手动唤醒**: 通过命令手动唤醒（可选）

**AI决定自动回复**:
- **AI判断**: 使用 AI 模型判断是否应该回复以及回复内容
- **提示词变量**: 
  - `{sleep_state}` - 当前睡眠状态
  - `{sleep_duration}` - 已睡眠时长
  - `{message_count}` - 收到的消息数量
  - `{message_content}` - 消息内容
  - `{caller_name}` - 发送者名称
  - `{relationship}` - 与发送者的关系
- **判断标准**:
  - 浅睡时可能回复重要消息
  - 深睡时不回复
  - 关系亲密的用户可能得到回复
  - 紧急消息可能得到回复

```python
async def should_reply_during_sleep(self, message: MaiMessages) -> Tuple[bool, str]:
    """AI判断睡眠期间是否应该回复"""
    if not self.get_config("sleep.ai_reply_enabled", False):
        return False, ""
    
    # 构建提示词
    prompt = self._get_prompt(
        "sleep_reply_judgment",
        sleep_state=self.sleep_state.value,
        sleep_duration=self._get_sleep_duration(),
        message_count=self._get_message_count_during_sleep(),
        message_content=message.content,
        caller_name=message.sender_name,
        relationship=self._get_relationship(message.sender_id)
    )
    
    # 调用AI判断
    success, response = await llm_api.generate_with_model(
        prompt=prompt,
        model_config=self._get_model_config(self.get_config("sleep.ai_model", "replyer")),
        temperature=0.7,
        max_tokens=500
    )
    
    if success:
        result = json.loads(response)
        return result.get("should_reply", False), result.get("reply_content", "")
    
    return False, ""
```

**打扰唤醒机制**:
- **浅睡唤醒**: 浅睡状态下，连续收到多条消息可能被吵醒
  - 消息频率阈值：1分钟内超过3条消息
  - 唤醒概率：浅睡50%，深睡10%
- **重要消息**: 关系亲密的用户消息可能唤醒
  - 亲密度 > 60（好友及以上）
  - 唤醒概率：浅睡70%，深睡30%
- **关键词唤醒**: 包含紧急关键词的消息可能唤醒
  - 关键词：`紧急`、`救命`、`快点`、`重要`等
  - 唤醒概率：浅睡90%，深睡50%

```python
def check_disturbance_wake(self, message: MaiMessages) -> bool:
    """检查是否应该被打扰唤醒"""
    if self.sleep_state not in [SleepState.LIGHT_SLEEP, SleepState.DEEP_SLEEP]:
        return False
    
    # 1. 检查消息频率
    if self._get_recent_message_count(60) > 3:
        wake_probability = 0.5 if self.sleep_state == SleepState.LIGHT_SLEEP else 0.1
        if random.random() < wake_probability:
            return True
    
    # 2. 检查关系亲密度
    relationship = self._get_relationship(message.sender_id)
    if relationship and relationship.intimacy > 60:
        wake_probability = 0.7 if self.sleep_state == SleepState.LIGHT_SLEEP else 0.3
        if random.random() < wake_probability:
            return True
    
    # 3. 检查紧急关键词
    urgent_keywords = ["紧急", "救命", "快点", "重要", "急事"]
    if any(keyword in message.content for keyword in urgent_keywords):
        wake_probability = 0.9 if self.sleep_state == SleepState.LIGHT_SLEEP else 0.5
        if random.random() < wake_probability:
            return True
    
    return False
```

**睡眠期间行为**:
- ✅ 拦截所有消息，不回复（ON_MESSAGE 事件处理器）
- ✅ AI判断是否回复及回复内容
- ✅ 可被消息打扰唤醒（浅睡概率高，深睡概率低）
- ✅ 不执行日程活动
- ✅ 不生成随机事件
- ✅ 疲劳度逐渐降低（每分钟降低 0.5-1）
- ✅ 健康度逐渐恢复（每分钟恢复 0.1-0.2）
- ✅ 饥饿度保持不变或缓慢增加
- ✅ 记录睡眠期间的消息数量和内容

**睡眠状态检查函数**:
```python
def check_sleep_state(self, current_time: datetime, schedule: List[Dict]):
    """检查并更新睡眠状态"""
    # 1. 基于日程检查睡眠状态（最高优先级）
    self.check_schedule_based_sleep(current_time)
    
    # 2. 检查是否应该入睡（日程未触发时）
    if self.sleep_state == SleepState.AWAKE:
        if self._should_sleep_by_fatigue() or self._should_sleep_by_time():
            self._start_sleeping(current_time)
    
    # 3. 检查是否应该醒来（日程未触发时）
    elif self.sleep_state in [SleepState.LIGHT_SLEEP, SleepState.DEEP_SLEEP]:
        if self._should_wake_by_duration() or self._should_wake_by_time():
            self._start_waking_up(current_time)
    
    # 4. 更新睡眠状态转换
    self._update_sleep_transition(current_time)
```

**消息拦截逻辑**:
```python
async def handle_message(self, message: MaiMessages):
    """处理消息，睡眠期间拦截"""
    if not self._is_sleeping():
        return False, True, None, None, None  # 不拦截
    
    # 1. 检查是否应该被打扰唤醒
    if self.check_disturbance_wake(message):
        await self._wake_up_by_disturbance()
        return False, True, None, None, None  # 不拦截，正常处理
    
    # 2. AI判断是否应该回复
    should_reply, reply_content = await self.should_reply_during_sleep(message)
    
    if should_reply and reply_content:
        await self.send_text(reply_content)
        return True, True, reply_content, None, None  # 拦截但回复
    
    # 3. 使用默认自动回复
    default_reply = self.get_config("sleep.sleep_reply", "")
    if default_reply:
        await self.send_text(default_reply)
        return True, True, default_reply, None, None  # 拦截并回复
    
    return True, True, None, None, None  # 拦截不回复
```

- **固定增长**: 每次互动固定增加亲密度（可配置增长率）

**AI判断标准**:
- 正向互动（友好、有趣、支持等）应该增加亲密度
- 负向互动（敌对、攻击、冷漠等）不应该增加亲密度
- 中性互动可以少量增加或不增加
- 亲密度越高，增加的幅度应该越小
- 互动次数越多，增加的幅度应该越小

**亲密度衰减**:
- 定期衰减（默认24小时）
- 可配置衰减率
- 家人、伴侣、拉黑用户不衰减

**关系类型自动更新**:
- 0-19: 陌生人
- 20-39: 熟人
- 40-59: 朋友
- 60-79: 好友
- 80-100: 挚友

#### 2.5.3 互动记录
**功能描述**: 自动记录与用户的互动历史。

**记录内容**:

**自动触发**:

**睡眠状态判断**:

- `LIGHT_SLEEP`: 浅睡，拦截消息
- `DEEP_SLEEP`: 深睡，拦截消息
- `WAKING_UP`: 醒来中，拦截消息

**配置项**:
```toml

enabled = true

```

**拦截逻辑**:
```python
async def execute(self, message: MaiMessages):
    """执行睡眠拦截"""
    if not self._is_sleeping():
        return False, True, None, None, None  # 不拦截
    
    # 睡眠期间拦截消息
    reply = self.get_config("sleep.sleep_reply", "")
    if reply:
        await self.send_text(reply)
    
    return True, True, reply, None, None  # 拦截消息
```

### 6.2 关键设计决策（v1.1.0）

#### 6.2.1 提示词在配置文件中

**实现方式**:

- 首次运行时自动生成包含提示词的配置文件
- 支持用户自定义
- 留空使用默认提示词

#### 6.2.2 移除 i18n 系统

#### 6.2.3 自定义时间/日期API

**实现方式**:
- builtin: 使用内置datetime
- custom: 使用自定义API
- 配置URL和超时

#### 6.2.4 生病系统

**实现方式**:
- AI根据疲劳度、饥饿度、情绪、当前活动、人格特点判断
- 健康度越高越健康
- 生病后自动重新生成符合病情的日程
- 康复后自动重新生成正常日程

#### 6.2.5 习惯工具

**实现方式**:

## 九、总结

本插件设计并实现了一个完整的事件及人体模拟系统，包含以下核心功能：

1. **生理状态模拟**: 睡眠（含完整睡眠周期、日程联动、AI自动回复、打扰唤醒）、疲劳、饥饿、健康（生病系统）、情绪等状态
2. **日常活动模拟**: AI驱动的日程生成
3. **事件触发系统**: AI驱动的随机事件生成
4. **习惯系统**: 配置+AI生成，LLM可访问
5. **社交网络系统**: 用户关系管理、亲密度系统、互动记录
6. **环境感知**: 时间（可自定义）、节日
7. **状态管理**: 持久化、查询
8. **AI模型配置**: 支持9种模型配置类型
9. **提示词系统**: 提示词在配置文件中
10. **睡眠系统**: 完整的睡眠周期管理，与日程联动，AI智能回复，支持打扰唤醒

插件提供了 2 个 Action 组件、3 个 Command 组件、6 个 EventHandler 组件和 5 个 Tool 组件，共 16 个组件，全面覆盖了事件及人体模拟的各个方面。

通过这个插件，机器人将具有更真实的拟人化行为，能够模拟人类的日常活动、生理状态、生病过程、睡眠周期（包括智能日程联动、AI自动回复和打扰唤醒）和社交行为，使与机器人的交互更加自然和有趣。睡眠系统的实现让机器人能够真正"睡觉"，在睡觉时不回复消息，并且能够根据日程自动入睡和醒来，AI智能判断是否回复，甚至可以被重要消息吵醒，大大增强了拟人化体验。状态查询工具让 LLM 能够根据当前状态（疲劳度、饥饿度、健康度、情绪等）调整回复风格和内容，使交互更加个性化和真实。
