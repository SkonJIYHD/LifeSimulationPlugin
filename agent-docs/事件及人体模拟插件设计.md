# 事件及人体模拟插件设计文档（AI驱动版本 v1.6.0）

> 生成日期: 2026-01-18
> 插件名称: LifeSimulationPlugin
> 插件版本: 1.6.0
> 架构类型: AI驱动

---

## 一、插件概述

### 1.1 插件目标
创建一个AI驱动的事件及人体模拟插件，让机器人具有真实人类的生理状态、日常活动、社交行为和环境感知能力，使机器人更加拟人化和生动。

### 1.2 核心特性（AI驱动版本 v1.6.0）
- **AI驱动的日程生成**: AI根据人格、习惯和当前状态生成日程
- **AI驱动的随机事件生成**: AI根据当前情境生成随机事件
- **生病系统**: AI多维度判断是否生病，生病后自动调整日程
- **健康状态由事件决定**: 健康状态由随机事件和日程决定
- **习惯系统**: 习惯可以配置或由AI根据人格生成
- **节日API集成**: 通过API动态获取节假日信息
- **AI驱动的情绪判断**: AI根据多方面因素判断情绪
- **可编辑的AI提示词**: 提示词在配置文件中，可自定义
- **AI生成话语**: 所有对话由AI生成，不固定
- **只读生理状态**: 生理状态数据不能通过命令修改
- **自定义时间/日期API**: 支持用户自定义时间日期获取方式
- **可配置AI模型**: 支持9种模型配置类型
- **习惯工具**: LLM可调用工具获取习惯信息
- **社交网络系统**: 记录用户关系，实现个性化社交行为
- **亲密度系统**: 通过互动积累和衰减机制管理亲密度
- **关系管理**: 支持9种关系类型（陌生人、熟人、朋友、好友、挚友、家人、伴侣、敌人、拉黑）
- **关系设置工具**: LLM可以通过工具设置用户关系类型，包括敌人和拉黑
- **详细日志系统**: 提供结构化的日志记录，支持不同模块的日志分类（SCHEDULE、EVENT、EMOTION、SLEEP、SOCIAL、DEBUG）
- **丰富的测试指令**: 提供17个调试和测试命令，支持状态管理、日程系统、事件系统、功能测试等全方位测试
- **紧急关键词可配置**: 支持自定义紧急关键词列表，灵活控制睡眠唤醒条件
- **Dream消息过滤**: 正确识别和过滤MaiBot Dream系统消息，确保Dream系统正常工作
- **回复频率降低**: 根据当前活动类型自动调整回复频率，需要动手的活动降低回复概率

### 1.3 设计原则
1. **AI优先**: 尽可能让AI做决策，减少硬编码逻辑
2. **动态生成**: 日程、事件、情绪等都由AI动态生成
3. **拟人化**: 模拟真实人类的行为和决策过程
4. **可配置**: 提供灵活的配置选项，包括AI提示词
5. **状态保护**: 生理状态数据不可随意修改

## 二、功能模块设计

### 2.1 生理状态模拟模块

#### 2.1.1 睡眠/清醒状态
**功能描述**: 模拟人类的睡眠周期，包括入睡、深睡、浅睡、醒来等状态。

**状态定义**:
- `AWAKE`: 清醒状态
- `SLEEPY`: 困倦状态
- `FALLING_ASLEEP`: 入睡中
- `LIGHT_SLEEP`: 浅睡状态
- `DEEP_SLEEP`: 深睡状态
- `WAKING_UP`: 醒来中

**打扰唤醒机制**:
- **消息频率**: 1分钟内超过阈值数量的消息可能被吵醒
- **关系亲密度**: 关系亲密的用户（亲密度 > 阈值）可能唤醒
- **紧急关键词**: 包含紧急关键词（如"紧急"、"救命"、"快点"、"重要"、"急事"等）的消息可能唤醒
- **睡眠深度**: 浅睡唤醒概率高，深睡唤醒概率低
- **Dream消息过滤**: MaiBot Dream系统发送的消息不会被睡眠处理器拦截，确保Dream系统正常工作
  - Dream消息由机器人自己发送（sender_id == bot_id）
  - 睡眠处理器会检测消息是否来自Dream系统，如果是则允许通过

**紧急关键词配置**:
```toml
[sleep]
emergency_keywords = "紧急,救命,快点,重要,急事"  # 紧急关键词列表（逗号分隔）
```
- 支持自定义紧急关键词列表
- 灵活控制睡眠唤醒条件

#### 2.1.2 疲劳度
**疲劳度范围**: 0-100

- 21-40: 精力良好
- 41-60: 轻微疲劳
- 61-80: 明显疲劳
- 81-100: 严重疲劳

**变化规则**:

**配置项**:


#### 2.1.4 健康状态（生病系统）
**功能描述**: 模拟人类的健康状态，影响行为和状态。

**健康状态类型**:
- `HEALTHY`: 健康
- `RECOVERING`: 康复中
- `SLIGHTLY_ILL`: 轻微不适
- `ILL`: 生病
- `SERIOUSLY_ILL`: 严重生病

**健康度范围**: 0-100（越高越健康）
- 80-100: 健康
- 60-79: 康复中
- 40-59: 轻微不适
- 20-39: 生病
- 0-19: 严重生病

**生病系统特点**:
- AI多维度判断是否生病（疲劳度、饥饿度、情绪、当前活动、人格特点）
- **疾病诊断系统**: 当健康状态变化时，AI自动诊断具体疾病
  - 疾病信息包含：疾病名称、生病原因、症状描述、治疗建议
  - AI根据当前状态、人格特点、个人习惯进行诊断
  - 不同健康状态对应不同严重程度的疾病
- 生病后自动重新生成符合病情的日程
  - 日程中包含医疗活动（如"计划服用感冒药"、"安排测量体温"）
  - 根据疾病症状安排合适的活动
  - 根据治疗建议安排医疗活动
  - 根据疾病严重程度调整休息时间
- 康复后自动重新生成正常日程
- 健康度越高越健康

**配置项**:
```toml
[schedule]
illness_system_enabled = true
illness_probability_multiplier = 1.0
auto_regenerate_on_illness = true
```

**疾病诊断提示词**:
```toml
illness_diagnosis = """你是一个医疗诊断助手，需要根据机器人的当前状态诊断疾病。

当前状态：
- 当前时间：{current_time}
- 当前日期：{current_date}
- 当前健康状态：{health_status}
- 当前疲劳度：{fatigue_level}/100
- 当前饥饿度：{hunger_level}/100
- 当前情绪：{current_emotion}

人格特点：
{personality}

个人习惯：
{habits}

请根据当前状态诊断疾病，格式为JSON对象，包含：
- illness_name: 疾病名称（如感冒、发烧、胃痛、头痛、疲劳综合征等）
- illness_reason: 生病原因（如过度劳累、饮食不当、着凉、压力过大等）
- illness_symptoms: 症状描述（详细说明症状表现）
- illness_treatment: 治疗建议（如休息、服药、饮食调整等）

注意：
1. 如果健康状态是 healthy，则 illness_name 为空字符串，其他字段也留空
2. 如果健康状态不是 healthy，则必须填写所有字段
3. 疾病名称要具体，不要笼统
4. 生病原因要合理，符合当前状态
5. 症状描述要生动具体
6. 治疗建议要切实可行
7. 不同健康状态对应不同严重程度的疾病：
   - recovering (60-79): 轻微疾病或康复期（如轻微感冒、消化不良）
   - slightly_ill (40-59): 中等疾病（如重感冒、发烧、胃炎）
   - ill (20-39): 严重疾病（如重感冒高烧、急性胃炎）
   - seriously_ill (0-19): 非常严重疾病（如重度肺炎、急性肠胃炎）

请只返回JSON对象，不要有其他内容。"""
```

#### 2.1.6 回复频率降低功能
**功能描述**: 根据当前活动类型自动调整回复频率，需要动手的活动降低回复概率。

**配置项**:
```toml
[reply_reduction]
enabled = true                                      # 是否启用回复频率降低功能
reduction_activities = "work,study,exercise,medical"  # 需要动手的活动类型列表
reduction_factor = 0.5                              # 回复概率降低因子（0.0-1.0）
```

**可用活动类型**:
- `work` - 工作/学习（如：计划开始工作、准备学习、安排编程任务）
- `leisure` - 休闲娱乐（如：计划玩游戏、准备看电影、安排休息时间）
- `meal` - 用餐（如：计划早餐、安排午餐、准备晚餐）
- `sleep` - 睡眠（如：计划睡觉、准备午休）
- `exercise` - 运动（如：计划跑步、准备健身、安排散步）
- `study` - 学习（如：计划阅读、准备复习、安排学习时间）
- `other` - 其他（如：计划购物、准备外出、安排其他事务）
- `rest` - 休息（如：计划休息、准备小憩、安排放松时间）
- `medical` - 医疗（如：计划就医、准备治疗、安排体检）

**推荐配置**:
- 专注模式: `"work,study,exercise,medical"` - 工作、学习、运动、医疗时降低回复
- 轻松模式: `"exercise,other"` - 仅运动、其他事务时降低回复
- 严格模式: `"work,study,exercise,other,medical"` - 大部分活动都降低回复

**回复概率降低因子**:
- `0.0` - 不降低回复概率
- `0.3` - 降低30%回复概率（轻微降低）
- `0.5` - 降低50%回复概率（中等降低，推荐）
- `0.7` - 降低70%回复概率（大幅降低）
- `1.0` - 降低100%回复概率（完全不回复）

**工作原理**:
- 当机器人进行需要动手的活动时，自动降低回复频率
- 降低因子存储在消息的 `additional_data` 中，供下游处理使用
- 实际回复概率 = 原始回复概率 × (1 - reduction_factor)

#### 2.5.2 亲密度系统
**功能描述**: 通过互动积累和衰减机制管理亲密度。

**亲密度增长方式**:
- **AI判断**: AI根据互动内容、用户特征、当前关系和情绪判断是否增加亲密度及增加多少（推荐）
- **概率增长**: 每次互动按概率增加亲密度（可配置概率）
- **固定增长**: 每次互动固定增加亲密度（可配置增长率）

**AI判断标准**:
- 正向互动（友好、有趣、支持等）应该增加亲密度
- 负向互动（敌对、攻击、冷漠等）不应该增加亲密度
- 中性互动可以少量增加或不增加
- 亲密度越高，增加的幅度应该越小
- 互动次数越多，增加的幅度应该越小

**亲密度衰减**:
- 定期衰减（默认24小时）
- 可配置衰减率
- 家人、伴侣、拉黑用户不衰减

**关系类型自动更新**:
- 0-19: 陌生人
- 20-39: 熟人
- 40-59: 朋友
- 60-79: 好友
- 80-100: 挚友

#### 2.5.3 互动记录
**功能描述**: 自动记录与用户的互动历史。

**记录内容**:
- 互动类型（消息等）
- 互动时间
- 互动次数
- 消息内容（用于AI判断）

**自动触发**:
- 每次收到消息时自动记录
- 根据增长方式更新亲密度
- 自动更新关系类型

**配置项**:
```toml
[social_network]
enabled = true
intimacy_growth_method = "ai"  # 增长方式: ai/probability/fixed
intimacy_growth_rate = 1       # 固定增长率（fixed方式）
intimacy_growth_probability = 0.5  # 增长概率（probability方式）
intimacy_ai_model = "replyer"  # AI模型（ai方式）
intimacy_decay_rate = 0.1
decay_interval = 86400
```

**AI提示词**:
- `intimacy_judgment`: 亲密度判断提示词，支持变量替换
  - `{user_name}` - 用户名
  - `{user_traits}` - 用户特征
  - `{relationship_type}` - 关系类型
  - `{intimacy}` - 当前亲密度
  - `{interaction_count}` - 互动次数
  - `{message_content}` - 消息内容
  - `{current_emotion}` - 当前情绪

### 2.6 AI模型配置

#### 2.6.1 可用模型配置

**模型配置格式**:
- **格式1**: 使用预定义模型类型
  ```toml
  schedule_model = "replyer"
  ```
- **格式2**: 指定具体模型名称（推荐）
  ```toml
  schedule_model = "replyer:gpt-4"
  schedule_model = "replyer:claude-3-sonnet"
  schedule_model = "tool_use:gpt-4-turbo"
  ```

**可用模型配置类型**:
- **utils**: 工具模型（表情包、取名、关系、情绪等）
- **tool_use**: 工具调用模型
- **replyer**: 回复生成模型
- **planner**: 决策模型
- **vlm**: 图像识别模型
- **voice**: 语音识别模型
- **embedding**: 嵌入模型
- **lpmm_entity_extract**: 实体提取模型
- **lpmm_rdf_build**: RDF构建模型

**配置项**:
```toml
[ai]
schedule_model = "replyer"           # 日程生成模型
event_model = "tool_use"              # 随机事件生成模型
emotion_model = "planner"            # 情绪判断模型
```

**说明**:

- 如果找到多个匹配，优先选择完全匹配的
- 如果找不到匹配的模型，会使用第一个可用模型

### 4.1 日志系统设计

#### 4.1.1 日志分类
插件采用结构化的日志记录系统，使用不同的标签来区分不同模块的日志：

| 日志标签 | 说明 | 记录内容 |
|---------|------|---------|
| `[SCHEDULE]` | 日程生成相关 | 当前时间、日期、节日、人格、习惯、健康状态、LLM调用信息、生成结果 |
| `[EVENT]` | 随机事件生成 | 当前时间、人格、习惯、状态信息、事件生成结果 |

- `DEBUG`: 详细的调试信息，包括所有输入参数、中间结果、详细状态

- `WARNING`: 警告信息，包括潜在问题、异常情况但不影响正常运行

## 六、实现说明（v1.1.0）

### 6.1 已实现功能

#### 6.1.1 核心架构
- ✅ 插件主类 `LifeSimulationPlugin`
- ✅ 状态管理类 `LifeState`
- ✅ 提示词系统（提示词在配置文件中）
- ✅ 节日API `HolidayAPI`
- ✅ 后台任务跟踪机制
- ✅ 调度器循环
- ✅ 时间API `TimeAPI`（支持自定义）

#### 6.1.2 AI生成系统
- ✅ **AI日程生成** (`_generate_schedule`)
  - 根据人格、习惯、当前状态生成日程
  - 考虑时间、星期、周末、节假日
  - 考虑健康状态、疲劳度、饥饿度
  - 日程包含时间、活动类型、描述、优先级
  - 每天自动重新生成（可配置）
  - 生病时自动重新生成符合病情的日程

- ✅ **AI随机事件生成** (`_generate_random_event`)
  - 根据当前情境生成随机事件
  - 事件类型包括健康、社交、工作、休闲、情绪等
  - 事件包含对健康、疲劳、饥饿、情绪的影响
  - 事件有发生概率
  - 生病系统：AI多维度判断是否生病
  - 概率可控（可配置）

- ✅ **AI情绪判断** (`_judge_emotion`)
  - 根据多方面因素判断情绪
  - 考虑时间、当前活动、生理状态
  - 考虑最近消息
  - 考虑人格特点
  - 返回情绪类型、强度、原因

- ✅ **AI习惯生成** (`_generate_habits`)
  - 根据人格特点生成个人习惯
  - 包括说话习惯、行为习惯、兴趣爱好
  - 包括偏好设置
  - 首次运行时自动生成

#### 6.1.3 提示词系统
- ✅ **提示词在配置文件中**
  - 不再硬编码在代码中
  - 所有提示词都在 `config.toml` 中
  - 支持自定义
  - 首次运行自动生成包含提示词的配置文件

- ✅ **日程生成提示词**
  - 根据健康状态调整日程
  - 生病时安排医疗活动和休息

- ✅ **随机事件生成提示词**
  - 包含生病系统详细说明
  - 生病类型和影响值

### 6.2 关键设计决策（v1.1.0）

#### 6.2.1 提示词在配置文件中
**决策**: 所有提示词都在配置文件中，不再硬编码。

**实现方式**:
- 提示词存储在 `config.toml` 的 `[prompts]` 部分
- 首次运行时自动生成包含提示词的配置文件
- 支持用户自定义
- 留空使用默认提示词

#### 6.2.2 移除 i18n 系统
**决策**: 移除国际化系统，简化代码结构。

**原因**: 用户反馈 i18n 没什么用。

#### 6.2.3 自定义时间/日期API
**决策**: 支持用户自定义时间日期获取方式。

**实现方式**:
- builtin: 使用内置datetime
- custom: 使用自定义API
- 配置URL和超时

#### 6.2.4 生病系统
**决策**: AI多维度判断是否生病，生病后自动调整日程。

**实现方式**:
- AI根据疲劳度、饥饿度、情绪、当前活动、人格特点判断
- 健康度越高越健康
- 生病后自动重新生成符合病情的日程
- 康复后自动重新生成正常日程

#### 6.2.5 习惯工具
**决策**: 提供工具让LLM访问习惯信息。

**实现方式**:
- `GetHabitsTool` 工具组件
- 可供LLM调用
- 返回格式化的习惯信息

## 八、总结

本插件设计并实现了一个完整的事件及人体模拟系统，包含以下核心功能：

1. **生理状态模拟**: 睡眠、疲劳、饥饿、健康（生病系统）、情绪等状态
2. **日常活动模拟**: AI驱动的日程生成
3. **事件触发系统**: AI驱动的随机事件生成
4. **习惯系统**: 配置+AI生成，LLM可访问
5. **社交网络系统**: 用户关系管理、亲密度系统、互动记录
6. **环境感知**: 时间（可自定义）、节日
7. **状态管理**: 持久化、查询
8. **AI模型配置**: 支持9种模型配置类型，支持使用 `类型:模型名称` 格式指定具体模型
9. **提示词系统**: 提示词在配置文件中
10. **日志系统**: 结构化的日志记录，支持不同模块的日志分类
11. **测试指令**: 丰富的调试和测试命令，支持全方位测试
12. **紧急关键词可配置**: 支持自定义紧急关键词列表，灵活控制睡眠唤醒条件
13. **Dream消息过滤**: 正确识别和过滤MaiBot Dream系统消息，确保Dream系统正常工作
14. **回复频率降低**: 根据当前活动类型自动调整回复频率，需要动手的活动降低回复概率

插件提供了 2 个 Action 组件、20 个 Command 组件（3个用户命令 + 17个调试命令）、5 个 EventHandler 组件和 5 个 Tool 组件，全面覆盖了事件及人体模拟的各个方面。

通过这个插件，机器人将具有更真实的拟人化行为，能够模拟人类的日常活动、生理状态、生病过程和社交行为，使与机器人的交互更加自然和有趣。同时，详细的日志记录和丰富的测试指令大大提升了开发调试效率和问题排查能力。紧急关键词可配置和Dream消息过滤功能进一步完善了睡眠系统，回复频率降低功能使机器人能够根据当前活动智能调整回复行为。
